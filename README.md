# Claude Code Linear Agent (unofficial)

A self-hosted Linear agent for your own workspace. Delegate a Linear issue to **Claude Code**, and a [Claude Code on the web](https://code.claude.com/docs/en/claude-code-on-the-web) session starts on **the delegating person's own Claude account**. The session works in your repository and opens a pull request as that person. Its plan, progress and result appear in the issue's agent session, the way Linear's built-in agents do.

> An unofficial integration, not made or supported by Anthropic or Linear. It relies on the Claude Code [routines fire API](https://platform.claude.com/docs/en/api/claude-code/routines-fire), which is experimental.

## How it works

```
Linear issue delegated to "Claude Code"
  -> AgentSessionEvent webhook  -> this app (Vercel)
  -> fires the delegator's Claude Code routine (scheduled task) over its API trigger
  -> cloud session clones your repo, does the work, opens a PR
  -> session curls progress back to /api/runs/<id>/events
  -> app relays it to Linear as plan updates, thoughts, actions, PR link, final response
```

- **Per-user accounts.** Everyone connects their own Claude account at `/connect`: a read-only Linear sign-in, then the fire URL and token of a Claude Code task they create. Tokens are stored AES-256-GCM encrypted.
- **Follow-ups.** A reply in the issue's agent thread reaches a running session on its next progress report. If the session has finished, the reply starts a continuation session that carries the earlier conversation.
- **Stop.** Linear's Stop makes the next callback return `stop`/410, and the session halts.
- **Watchdog.** A cron job posts a note when a session goes quiet (for example, while it waits on an approval) and gives up after 2 hours.
- **Pull requests.**
  - Branches are named `feat/<issue>-…` or `fix/<issue>-…`.
  - PRs target `DEFAULT_BASE_BRANCH` and carry a `Fixes <ID>` line, so Linear's GitHub integration links them.
  - The "Generated by Claude Code" footer is stripped.
- **Issue status.** Delegating moves the issue to the team's first *started* state.

## What you need

- **Vercel:** a project on the **Pro** plan. The watchdog cron runs every 5 minutes, and Hobby only allows daily crons.
- **Upstash Redis:** from the Vercel Marketplace.
- **Linear:** workspace admin rights, to create a private OAuth app.
- **Claude:** each user needs a Pro, Max, Team or Enterprise plan with Claude Code on the web and GitHub connected. On Team or Enterprise, an Owner must enable scheduled tasks (routines).

## Configuration

| Variable | Purpose |
|---|---|
| `PUBLIC_BASE_URL` | Production URL, with no trailing slash. It must be a stable public host. |
| `LINEAR_CLIENT_ID`, `LINEAR_CLIENT_SECRET`, `LINEAR_WEBHOOK_SECRET` | The Linear OAuth app |
| `BOT_SIGNING_SECRET` | Signs per-run callback tokens, OAuth state and session cookies |
| `TOKEN_ENCRYPTION_KEY` | Encrypts stored routine tokens |
| `CRON_SECRET` | Authenticates Vercel cron calls |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis, set by the integration |
| `DEFAULT_REPOSITORY` | Repo sessions work in by default, for example `your-org/your-repo` |
| `DEFAULT_BASE_BRANCH` | Base branch for that repo's PRs (default `main`) |
| `ROUTINES_JSON` | Optional admin fallback: `{"<linear-user-id>": {"fireUrl", "token"}}` |

## Development

```sh
bun run dev        # http://localhost:3000
bun run test       # vitest
bun run typecheck
```

The session-to-app callback leg only works against the deployed host. The cloud session's auto-mode safety check blocks POSTs to tunnels and other unnamed hosts.

## Limits

These come from the routines API:
- **One-way:** the API can start a session, but can't read, message or cancel one. Everything here works around that through the callback protocol.
- **Rate limits:** 30 starts per hour per routine, and 100 per hour per account.
- **Session titles:** every session is titled after the routine's name.
